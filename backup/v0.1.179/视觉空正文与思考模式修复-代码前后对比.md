## 修改前

视觉请求没有显式控制思考模式：

```json
{
  "model": "qwen3.5-9b-vlm",
  "max_tokens": 300,
  "response_format": {"type": "json_schema"}
}
```

响应解析只读取：

```text
choices[0].message.content
```

当服务返回 HTTP 200、`content=""`、但 `reasoning_content` 有内容时，应用会把空正文
统一归类为“不是有效 JSON”，然后对空文本尝试 JSON 格式修复和纯文本兜底。

## 修改后

所有视觉请求统一增加：

```json
{
  "temperature": 0,
  "chat_template_kwargs": {"enable_thinking": false}
}
```

单帧结构化输出预算从 300 提高到 640。首次 HTTP 200 空正文时：

1. 读取响应信封，只统计 reasoning 字符数、`finish_reason` 和 token 数；
2. 不记录 reasoning 正文、assistant 正文、图片 Base64、prompt 或 API Key；
3. 以同一 messages 和图片重试一次；
4. 保持关闭思考，并将输出预算从 640 提高到 1280；
5. 第二次仍为空则停止，不发起第三次格式修复请求。

新增响应信封结构：

```cpp
struct AssistantResponseEnvelope {
    QString content;
    qsizetype reasoningLength;
    QString finishReason;
    qint64 promptTokens;
    qint64 completionTokens;
    qint64 totalTokens;
};
```

空正文错误分类：

```text
finish_reason=length + reasoning
  -> 达到输出 token 上限，尚未生成最终 JSON（仅返回推理内容）
reasoning 存在
  -> HTTP 200，但最终正文为空（仅返回推理内容）
均不存在
  -> HTTP 200，但最终正文为空
```

## 新增回归

- reasoning-only + `finish_reason=length` 信封解析。
- 普通 HTTP 200 空正文分类。
- 所有单帧请求携带关闭思考与确定性温度。
- 首次空正文、第二次有效时成功恢复。
- 连续两次空正文时严格停止在 2 个原始请求，不触发格式修复和纯文本兜底。
