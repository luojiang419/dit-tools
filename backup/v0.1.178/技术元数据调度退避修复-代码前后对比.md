## 修改前

`runMetadataJob()` 和 `runThumbnailJob()` 已会在资源等待失败时自行安排 5 秒退避，
但 `runMediaJobs()` 忽略两个函数的返回值，并在末尾无条件安排 250 ms 立即续批：

```cpp
if (thumbnailJobId > 0) {
    runThumbnailJob(...);
}
if (metadataJobId > 0) {
    runMetadataJob(...);
}
scheduleSourceRootRetry(projectDatabasePath,
                        sourceRootId,
                        ImmediateContinuationDelayMs);
```

`scheduleSourceRootRetry()` 采用“更早定时器优先”的合并规则，因此 250 ms 会替代已经
安排的 5 秒退避。下一轮又会创建新任务，造成任务中心反复出现“准备读取技术参数
0/128”。

## 修改后

`runMediaJobs()` 合并两个子任务的执行结果。只有实际执行的任务全部正常结束时，
才安排 250 ms 续批；任何一个子任务返回失败/已退避，外层不再覆盖其定时器：

```cpp
bool shouldContinueImmediately = true;
if (thumbnailJobId > 0) {
    shouldContinueImmediately = runThumbnailJob(...) ;
}
if (metadataJobId > 0) {
    shouldContinueImmediately = runMetadataJob(...)
        && shouldContinueImmediately;
}
if (shouldContinueImmediately) {
    scheduleSourceRootRetry(projectDatabasePath,
                            sourceRootId,
                            ImmediateContinuationDelayMs);
}
```

新增 `metadataResourceCancellationKeepsBackoff()` 回归测试：

1. 前台任务占用 Heavy I/O；
2. 元数据任务进入“等待执行资源”；
3. 切换协调器 generation 取消旧等待；
4. 验证失败任务显示“已安排自动重试”；
5. 验证 750 ms 内元数据任务总数仍为 1，没有被 250 ms 立即重派。
