### Authenticode 发布契约

- 发布时从 `WINDOWS_SIGNING_CERTIFICATE_BASE64` 和 `WINDOWS_SIGNING_CERTIFICATE_PASSWORD` GitHub Secrets 导入 PFX。
- 签名者 SHA-256 从真实证书派生，不手填、不伪造，并编译到更新客户端。
- 主程序和安装器使用 SHA-256 Authenticode 与 RFC 3161 时间戳签名，签名后立即按证书 SHA-256 复核。
- `verify_release_artifact.ps1 -RequireSignature` 在发布前再次复核。
- 无论成功失败，CI 都会清理临时 PFX 和导入的证书。

## 已确认的外部阻塞

### 1. 仓库没有代码签名 Secrets

`gh secret list --repo luojiang419/dit-tools` 返回空。因此当前无法完成“有效 Authenticode + 客户端固定签名者”验收。

不可用自签名证书冒充：普通用户设备不信任自签名根，`Get-AuthenticodeSignature` 不会得到可靠的 `Valid` 发布状态。

### 2. 仓库没有 GPU runner

`gh api repos/luojiang419/dit-tools/actions/runners` 返回 `total_count=0`。仓库是个人公开仓库，当前 `windows-2022` 标准 runner 只有 CPU 规格；GitHub 的 GPU larger runner 需要组织/Team 或 Enterprise 方案。

因此不能在现有托管 runner 上把真实 Qwen Vulkan GPU 测试设为发布阻断门禁，也不能用 CPU 回落伪装 GPU 通过。

## 待用户决策
