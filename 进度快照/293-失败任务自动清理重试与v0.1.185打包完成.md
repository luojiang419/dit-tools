# 293 - 失败任务自动清理重试与 v0.1.185 打包完成

## 本轮目标

- 分析任务中心长期停在 `0/37638`、`0/2421` 的运行日志与项目数据库状态。
- 实现未完成媒体任务自动续跑、瞬时失败自动重试、失败任务记录自动清理。
- 避免把 3.5 万个永久不支持的 RAW/视频失败项全部无条件重试。
- 自动递增版本并生成可交付的 Windows 安装包。

## 根因结论

1. 原媒体任务一次领取 128 项后，缩略图阶段会长期持有重型 I/O 资源，元数据任务只能等待。
2. FFmpeg 单次调用可等待 60 秒，RAW 多后端串行尝试最坏可超过 90 秒，缺少整项看门狗时界面长时间没有进度变化。
3. 项目库中约 3.5 万个历史失败项大多是 CR2/CR3、MOV、PSD 等不支持或无效文件；无条件清空失败状态会造成更严重的重试风暴。
4. 旧调度完成一批后不会稳定、受控地自动领取下一批，未完成任务可能一直留在库中。
5. 新重试字段首次实现时发现：默认构造的空 `QString` 会被 SQLite 绑定成 `NULL`，触发 `NOT NULL` 写入失败并形成重复派发；现已改为显式空文本并加入回归覆盖。

## 已完成内容

### 1. 数据库持久化重试状态

- 项目数据库版本从 `8` 升级到 `9`。
- `thumbnail` 新增：
  - `retry_count`
  - `next_retry_at`
  - `retry_policy_version`
  - `failure_kind`
- 新增按状态、到期时间和策略版本查询的重试索引。
- 旧数据库打开时自动补列、补索引，不删除原缩略图失败原因。

### 2. 自动重试策略

- 瞬时失败最多自动重试 3 次。
- 退避时间固定为：5 秒、30 秒、2 分钟。
- 达到上限后写为 `retry_exhausted`，不再自动重试。
- 永久不支持或无效文件写为 `permanent`，不进入自动重试。
- 旧 CR2/CR3 失败项在 RAW 能力升级后按策略版本仅补试一次。
- FFmpeg 启动失败、超时和典型临时 I/O 错误会传递 `retryable` 标志。

### 3. 自动续批与卡死保护

- 每个任务批次最多处理 128 项，完成后自动领取下一批。
- 缩略图和元数据不再整批长期持有 Heavy I/O 租约，改为逐文件获取和释放。
- SQLite 写入资源和 Heavy I/O 资源等待上限为 30 秒，超时后释放任务并安排重试。
- RAW 多后端解码增加 90 秒总看门狗，剩余时间会传递给单个 worker 请求。
- 未初始化的执行模块不再被无限重复派发，避免 250ms 的失败任务创建循环。
- 同一项目和素材源通过 active key 与单定时器去重，避免并发重复 worker。

### 4. 失败任务自动清理

- 新替代任务成功创建后，自动删除同素材源、同类型的旧 `Failed` 任务记录。
- 当前运行任务、其他素材源任务以及未被替代的失败任务保持不变。
- 单素材的最终失败原因继续保存在 `thumbnail.error_message`，便于诊断。

### 5. 测试与踩坑记录

- 新增/扩展测试：
  - 协调器等待超时。
  - 只清理由重试替代的失败任务。
  - 旧 RAW 策略升级补试。
  - 瞬时失败退避与计数持久化。
  - 重试耗尽保持终态。
  - 300 文件按 128 项分批自动续跑。
- 新增避坑指南：
  - `Windows-测试超时后残留进程占用EXE.md`
  - `Qt-SQLite空QString绑定NULL导致NOT-NULL失败.md`

## 关键代码前后对比

```text
修改前：失败缩略图只有 Failed 状态，没有失败分类、重试次数和下次执行时间。
修改后：持久化 retry_count / next_retry_at / retry_policy_version / failure_kind，重启软件后仍可继续正确退避。

修改前：一个缩略图批次长期持有执行资源，外部工具可以连续等待较长时间。
修改后：逐文件获取资源；协调器等待 30 秒封顶；RAW 整项 90 秒封顶。

修改前：历史失败项要么永久跳过，要么只能全量重置，存在重试风暴风险。
修改后：永久失败保持终态；瞬时失败最多重试 3 次；旧 CR2/CR3 仅按新策略补试一次。

修改前：旧 Failed 任务记录会长期留在任务中心。
修改后：替代重试任务创建成功后，仅清理同源同类型的旧 Failed 记录，素材级失败原因仍保留。
```
