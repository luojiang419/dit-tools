# 296 - 视觉思考模式与空正文单次重试修复完成

## 本轮目标

- 避免 LM Studio/Qwen 思考模式消耗输出预算后没有生成最终 JSON。
- 将 HTTP 200 空正文与普通 JSON 格式错误分开诊断。
- 空正文只重试一次原始视觉请求，不对空字符串执行格式修复。
- 日志只记录安全的结构化诊断，不泄露视觉内容和凭据。

## 已完成内容

### 1. 请求契约

- `makeChatPayload()` 统一加入 `temperature=0`。
- 统一加入 `chat_template_kwargs.enable_thinking=false`。
- 单帧复杂结构化 JSON 的 `max_tokens` 从 300 提高到 640。
- 单帧格式修复预算从 350 提高到 640。
- 保留既有 `json_schema` 响应格式兼容回退，不擅自开启可能破坏旧服务的严格模式。

### 2. 响应信封解析

新增 `AssistantResponseEnvelope`，解析：

- 最终 `content`。
- `reasoning_content` 或 `reasoning` 的字符数。
- `finish_reason`。
- prompt/completion/total token 统计。

reasoning 只在内存中用于长度判断，不写入日志。

### 3. 空正文单次原始请求重试

- 首次成功响应正文为空时，重发同一个 messages/图片请求一次。
- 重试继续显式关闭思考。
- 输出预算按原值翻倍，限制在 640 到 2048 之间。
- 第二次仍为空时停止，不进入第三次格式修复请求。
- 非空但 JSON 格式错误仍保留既有修复和纯文本兜底能力。

### 4. 错误分类和安全日志

- `finish_reason=length` 且存在 reasoning：
  `达到输出 token 上限，尚未生成最终 JSON（服务仅返回推理内容）`。
- reasoning 存在但非长度结束：
  `HTTP 200，但最终正文为空（服务仅返回推理内容）`。
- 没有 reasoning：
  `HTTP 200，但最终正文为空`。
- 日志只记录 finish reason、reasoning 字符数、token 数和重试预算。

### 5. 自动化回归

- 新增 reasoning-only 响应解析测试。
- 新增普通空正文分类测试。
- 新增请求关闭思考、温度和 640 token 检查。
- 新增空正文后原始请求单次重试成功测试。
- 新增连续空正文只发两次请求且不进入修复/兜底测试。
