# 290 - 失败任务删除与扫描假性卡死修复完成

## 已完成内容

- 失败、已完成、已取消任务支持单卡删除。
- 任务页顶部“清理已完成”改为“清理已结束”，可批量清理三类终态任务。
- 删除先持久化到项目数据库，成功后才移除内存卡片；重启后不会恢复已删除记录。
- 运行中、排队中任务在核心层被拒绝删除。
- 扫描任务总量未知时，不再显示容易长期停住的固定百分比，改为“扫描中/持续扫描中”。
- `ThemedProgressBar` 的 indeterminate 状态改为真实往返动画，任务页、任务详情和全局底栏统一接入。
- 保留扫描引擎原有每批 256 项的有界高吞吐写入策略，没有为提高视觉刷新频率牺牲百万级扫描性能。
- 根版本从 `0.1.182` 递增到 `0.1.183`。
- 新增构建避坑文档：`避坑指南/Windows-CMake版本缓存与错误编译器选择.md`。

## 根因证据

- 旧规则和旧单测明确要求 `clearCompletedJobs()` 只删除成功任务并保留失败任务，因此纯失败列表时按钮必然禁用。
- 现场已安装进程 `Responding=True`；日志中扫描项从 2,346 持续增长到 15,777，UI 心跳 P95 为 0～1ms，`sqlite_busy_count=0`。
- 实际扫描没有死锁；主要问题是目录总量未知时仍显示约 25% 的估算值，长时间不变造成“卡死”观感。

```cpp
bool removeFinishedJob(qint64 jobId);
void clearFinishedJobs();
```

