## 当前项目现状

- Qt 6 / C++ / QML / SQLite / FFmpeg Windows 桌面应用。
- 扫描枚举、媒体元数据和全局素材同步已有分页基础。
- 素材中心仍有同步查询/详情/拼图路径；任务进度仍可能在 UI 线程写库。
- 新视频策略采用 FFmpeg 过滤器生成候选后全片质量/哈希筛选，缺少独立时间覆盖记录。
- 搜索文档有增量队列，但失败消费缺少可靠重放；向量索引每个小批次保存完整文件。

## 技术方案

- 正确性契约先于实现：每个已复现问题先补测试，再修改代码。
- 前台只提交请求和应用有限结果；数据库、解码、索引和拼图进入各自工作执行器。
- 抽帧按时间窗口规划，必保首尾锚点；相似画面可复用分析，但不删除时间节点。
- 重建写新代并在验收后切换，失败保留当前有效代。
- 写入按数据库串行化、短事务；调度等待不占执行线程。
- 搜索消费采用持久水位/失败重放；向量索引采用批次末统一发布并逐步演进为快照。

## 已知问题

1. **构建可靠性**：旧构建目录仍保留乱码前缀，不能作为证据；新 `architecture-verified-utf8` 已使用 UTF-8 代码页生成正确前缀，并通过头文件触发重编译验证。JobEngine关闭排空生命周期仍待单独复核。
2. **扫描自锁**：`countWriterLease` 已在统计事务 commit 后、重新申请 reconcile writer lease 前释放；真实协调器下 legacy rescan 与定向扫描测试通过。
3. **扫描计数/兼容**：根目录求和已排除目录自身，旧临时扫描表父目录从 relative_path/name 推导，DatabaseManager 回填条件和查询计划已由 `FolderDatabaseMigrationTest` 复核；迁移大表成本仍需验收。
4. **抽帧（代码确认，未修完）**：terminalTolerance匹配后直接将候选timestampMs改成terminalSourceTimestampMs，不证明该JPEG来自末帧；fps策略生成的输出网格时间、缺日志时插值均不等于真实源PTS。短片失败回退也需避免把非采样原因的错误掩盖为成功。PerFrame仍受去重筛选，候选文件/时间戳集合仍随片长增长，尚无独立Coverage Manifest。
5. **重建（待故障注入）**：旧帧可延迟替换，但新run结果主要暂存内存，任务行与旧结果仍共享；重启恢复/未完成解析费用复用不足。部分失败路径、提交前取消、旧代可见状态应逐项验证。200个MiniMax请求并发仍可能造成高内存和重复请求；并发while选择不完整Skipped帧的退出条件需要优先复核。
6. **Job writer（代码确认/待测试）**：`waitForPersistence()` 等线程池但可能不处理watcher回调；`observeCompletion=false`批次结果被忽略，失败待办可能丢失。200ms timer持续restart可推迟进度落盘。失败的旧progress不能覆盖已完成终态，多个字段键的顺序、同ID跨项目和删除后ID复用均需约束。AppContext当前在其它后台生产者结束之前就waitForPersistence，需在所有生产者退出且已派发末尾更新后排空。任务创建/删除仍有同步写路径。
7. **UI（代码确认/待交互测试）**：generation只丢弃过期结果，QtConcurrent提交队列仍可能不断增长；详情页现有 240 帧/8 MiB 预算，但仍需处理请求队列、检索/导航兼容性与真实 UI 验收。异步化后的openSelectedProject改为“稍后重试”，全局快速搜索导航兼容性需检查。旧fetchDetail默认截断2000帧须核查全部调用方是否导致功能缺失。
8. **搜索（条件性风险）**：bulk生命周期各批分别持锁，多实例同时更新的最终快照互相覆盖风险未验证；外层HeavyIo和SqliteWriter仍覆盖整次同步。失败待办回补仅内存，旧失败change可能覆盖新事件，跨进程重放未完成。不能据此声称已实现事务outbox或不可变快照发布。
