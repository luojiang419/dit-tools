# Windows 测试超时后残留进程占用 EXE

## 现象

- 测试命令被外层工具终止后，重新编译出现 `LNK1104: 无法打开文件“xxxTest.exe”`。
- 源码编译阶段已经成功，只有链接测试可执行文件失败。

## 根因

外层 PowerShell 或测试调度命令超时，不一定会同步结束它启动的 QtTest 子进程。残留的测试进程仍持有原 EXE，Windows 链接器无法覆盖该文件。

## 处理方法

1. 先按测试进程的准确名称检查残留进程，不删除构建目录或对象文件。
2. 只结束与当前测试目标对应的残留测试进程。
3. 确认进程退出后重新链接。
4. 对预计会等待异步事件的测试设置足够的外层超时，避免同一目标重复并发编译。

## 避免方式

- 首次测试超时后先检查 `ctest` 和对应 `*Test.exe`，不要立即并行重跑构建。
- `LNK1104` 指向测试 EXE 时优先排查文件占用；不要通过清空整个构建缓存规避。
- 正式应用进程与测试进程要按完整路径区分，禁止误停用户正在使用的正式版程序。
