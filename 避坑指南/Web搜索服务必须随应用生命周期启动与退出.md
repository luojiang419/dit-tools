# Web 搜索服务必须随应用生命周期启动与退出

日期：2026-07-31

## 现象

浏览器访问 `http://127.0.0.1:17890/` 时显示 `ERR_CONNECTION_REFUSED`。

## 原因

- 当前运行的是旧安装版，旧版没有集成 Web 搜索服务。
- 直接运行构建目录 EXE 时，如果没有 Qt 运行时目录进入 `PATH`，程序可能立即退出，浏览器也会表现为端口拒绝连接。
- 仅在对象析构时停止服务，会让端口释放时机依赖关闭屏障和后台任务完成。

## 解决方案

1. 在完整桌面构建中创建并启动 `WebSearchService`。
2. 服务启动成功后绑定 `QCoreApplication::aboutToQuit`，立即调用 `stop()`。
3. 在 `AppContext` 析构开始时再次调用 `stop()`，作为异常退出路径的兜底。
4. 用包含 Qt 运行时的正式安装包运行，不要把未部署的构建目录 EXE 当作最终用户版本。

## 验收顺序

```text
启动新版软件
  ↓
GET /api/health 返回 {"ok":true}
  ↓
浏览器访问 /
  ↓
关闭软件
  ↓
17890 端口不再处于 LISTEN 状态
```

## 注意

如果本机访问正常但局域网设备访问失败，需要检查 Windows 防火墙对 `CineVault.exe` 的 TCP `17890` 入站规则；不要通过修改页面地址绕过服务未启动问题。
