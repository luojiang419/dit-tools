# Windows 磁盘卷根路径尾斜杠导致整卷扫描为空

## 现象

合成目录压力测试正常，但真实卷根（例如 `H:/`）扫描会在数毫秒内“成功”结束，`asset_count=0`。卷内实际存在文件，`QStorageInfo` 和 `QDirIterator` 也能枚举顶层目录。

## 根因

`ScanPathPolicy::isPathInside()` 直接使用 `root + '/'` 生成子路径前缀。普通目录根没有尾斜杠，因此正常；Windows 卷根经规范化后仍为 `H:/`，拼接结果变成 `H://`。于是 `H:/DCIM`、`H:/MISC` 等全部被误判为根路径之外，扫描器又会把根外路径安全地排除，最终形成无报错的空索引。

## 修复

生成比较前缀时先判断根路径是否已经以 `/` 结尾：已存在则直接使用，否则才追加 `/`。回归测试必须至少覆盖：

- `isPathInside("<卷根>/DCIM", "<卷根>") == true`；
- 真实移动卷根能索引业务文件；
- `System Volume Information` 仍被排除；
- 网络卷根的普通顶层目录不被误排除。

## 本机真实卷结果

修复后，`H:` exFAT 相机卡在 2.009 秒内索引 1,955 个业务文件，系统目录被排除；队列峰值 256，SQLite busy 为 0，峰值工作集约 17MiB。`X:`、`Y:` 两个 SMB 网络卷也能由产品的 `StorageVolumeService` 正确枚举并访问顶层路径。

不要只用 `QTemporaryDir` 子目录验证路径包含关系；它无法暴露卷根保留尾斜杠这一 Windows 特有边界。
